# CMP Prime V1 Manual Review Failures

Failed V1 branch: `prototype/cmp-prime-clean-action-led-v1`

Failed V1 commit: `d420d32a0fd2628c491793b5c056a4e23baacf78`

Failed V1 Netlify draft: `https://6a426ea53ab6e01a3b933a0e--spontaneous-truffle-1b110e.netlify.app`

Manual review verdict:

- Do not show CMP Prime V1 to Nick.
- Do not patch CMP Prime V1.
- Do not build from the V1 implementation.

CMP Prime V1 failed because:

1. It looked and felt too similar to older CMP versions.
2. Homepage wording "rental readiness, one property at a time" is too limiting because CMP should later support portfolio-wide features.
3. Add Property did not provide a proper address picker.
4. EPC data appeared too early and did not logically follow from postcode-only input.
5. Property questions were vague.
6. After the questions, the Property Brain became confusing.
7. Overview, Evidence Vault, Action Plan, Services and Monitoring felt like disconnected sections.
8. The journey was lost after reaching the main property screen.
9. Draft service request was confusing.
10. Some services should be bookable directly rather than only "request drafted".
11. Action Plan "resolve this action" only led to "add evidence", with no meaningful alternatives.
12. My Properties duplicated the same property several times with different next steps.
13. Ask CMP felt basic and did not behave like a normal AI input.
14. The prototype did not explain CMP within 10 seconds.
15. There was more than one obvious next action.
16. Evidence Vault felt disconnected from the next action.
17. It felt like an old CMP reskin rather than a new product.

Conclusion:

CMP Prime V1 should be preserved as a failed exploration but not used as the basis for V2.
